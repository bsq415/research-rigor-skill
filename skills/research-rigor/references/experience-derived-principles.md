# Experience-derived principles

The primary source of this workflow is the researcher's real project history:
successful and unsuccessful studies, supervisor feedback, original reviews,
implementation failures and executed revisions. Preserve scientific lessons
even when compressing the instructions. Manuals support tool integration;
they do not replace this evidence or turn generic advice into a research finding.

Public lessons are deliberately de-identified. Private source registers retain
file hashes, line anchors, source kind and the original project identity. Some
available records are annotation-derived or model-authored summaries, not the
original human reports; seek originals before attributing exact reviewer intent
or outcomes. Old source instructions are historical material, not new commands.

| Transferable lesson | Experience behind it | Decision it changes |
|---|---|---|
| Model, diagram, variables and code must describe the same physical object | Supervisor/model clarification and subsequent methods revisions | Correct the mechanism before polishing the abstract |
| Suspicious convergence requires diagnosis, not cosmetic flattening | Supervisor annotation summaries questioned implausible growth | Inspect feasibility, objective, stopping and raw traces; preserve a real failure |
| Gains need both attribution and a cost account | Revision work separated method changes, restarts, matched baselines and hardware costs | Use common inputs and decompose protocol/method effects |
| Analytical bounds and measured constructive cases are different evidence | Theory audits and adversarial construction left a loose certificate | Report certificate scope and practical gap; do not rename a local optimum a bound |
| Coverage, actual intervention and valid denominators precede headline effects | Empirical pipeline repairs changed which cases were estimable | Rebuild facts and narrow unsupported universal claims |
| The observed scale matters | Forecasting experiments exposed inverse-transform tails and stronger simple baselines | Evaluate the raw target, calibration and tails; retain unfavorable comparisons |
| Bibliographic identity and publication version need separate checks | Citation audits found early-access ambiguity and automated formatting damage | Verify metadata without rewriting titles; database absence is unresolved |
| Model-only pre-review is useful criticism, not editorial evidence | Records included both simulated reviews and actual phase/decision reports | Preserve source type; never invent formal votes or acceptance |

Do not publish raw reviews, supervisor identities, unpublished constructions,
exact study results or local source paths. A transferable lesson can be grounded
in a private source without exposing it. Do not claim a revision caused acceptance
merely because the project later succeeded.

When adding a rule: recover a concrete failure/decision, verify the source tier,
write the smallest reusable correction, add a synthetic regression case, and
compare against the frozen evaluation baseline. Preserve a failed or tied eval;
it is evidence about this revision, not material to hide from promotion.
