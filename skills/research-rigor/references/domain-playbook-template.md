# Domain playbook template

Adapt this to the researcher's domain using real project decisions, reviews and
failures. Do not invent expertise or infer an experiment caused publication.
Keep source tracing private and copy only de-identified lessons into the skill.

## Decision and evidence

- **Question:** which intervention, estimator or argument changes which decision?
- **Objects/population:** units, eligibility, sampling, measurement and target domain.
- **Information:** what is observed at decision time, with noise, timing and costs?
- **Main claim:** exact estimand/quantifiers, assumptions, expected evidence tier.
- **Nearest alternative:** closest prior work and strongest already-done argument.
- **Cheap falsifier:** an admissible boundary case or observable failure that kills the claim.
- **Independent check:** a different derivation, exact case, measurement or held-out replication.
- **Comparison:** feasible actions, information access, tuning budget and paired unit.
- **Boundary:** what remains unidentified, unmeasured or unsupported?

## Domain choices that change the workflow

| Area | Fill from the actual domain/project |
|---|---|
| Observational/social research | Confounding, selection, treatment timing, clustered units, missingness, causal assumptions |
| Biology/experimental science | Biological versus technical replicates, batch, randomization/blinding, assay controls, multiple testing |
| Theory/mathematics | Quantifiers, degenerate objects, branch/domain restrictions, constructive examples, proof obligations |
| Qualitative research | Recruitment, positionality, coding trail, contradictory cases, source attribution, transfer limits |
| Engineering/computation | Observation access, feasible constraints, cost, surrogate-to-target transfer, implementation oracle |

These are template prompts, not completed domain playbooks or claims of validated
biological/social-science expertise. Ground a completed playbook in actual primary
materials and domain review before using it for consequential interpretation.

## Lessons and execution

Record each lesson as `private source → observed failure/decision → transferable
rule → synthetic regression → scope limit`. Preserve failed routes, controls
that favor alternatives, and reviewer criticisms that were not substantiated.
Use only the currently unresolved stages of the [research paths](research-playbooks.md).
Begin with the light records; upgrade when a full protocol/controller helps.
