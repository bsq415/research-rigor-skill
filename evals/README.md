# Research-rigor evaluation baseline

先保存真实结果，再谈宣传。这里分开记录模型对照、工具功能回归和文档体积；它们回答不同问题。

## 首轮模型对照：没有测到提升

2026-10-11，本地已登录 Codex CLI，`gpt-6.1-sol`、`medium`，每题每条件一次，20 次生成和 20 次评分。任务顺序随机，独立临时会话、关闭工具、禁止宿主 skill 自动发现；两条件共享基础提示，处理组额外读冻结的 SKILL、理论和实验两份参考文件。评分在另一个盲化上下文进行，但仍为同模型临时评分，**没有人工独立复核，不能称客观人类评分**。

| 分析口径 | 无 skill | 有 skill | 结论 |
|---|---:|---:|---|
| v1.0.0 原始 10 题，冻结评分 | 40/40 | 40/40 | 持平；包含有缺陷的 T10 |
| 排除有缺陷 T10 的 9 题 | 36/36 | 36/36 | 持平 |
| 8 个陷阱识别 | 8/8 | 8/8 | 持平 |
| 有效干净对照 T09 | 1/1 | 1/1 | 两者均未误拦 |
| 修正 T10，单独 v1.0.1 补测 | 4/4 | 4/4 | 持平，不拼接成新的独立 10 题实验 |
| 更新入口后的完整 v1.0.1 十题回归 | 40/40 | 40/40 | 仍持平，未发现这组题上的回归 |

[原始答案、逐项评分与冻结材料](results/pilot-20261011-v100/summary.json)全部保留，包括 [answers.json](results/pilot-20261011-v100/answers.json)、[评分理由](results/pilot-20261011-v100/criterion-scores.csv)和 [rubric](results/pilot-20261011-v100/rubric.json)。评分表在答题时隐藏，发布版本只有合成任务，不含项目隐私。

**失败案例：评测题设计失误。** T10 原先只有 100 个测试样本，却给出狭窄置信区间且没说明计算方法；两组回答都提醒核实，原 rubric 却仍给满分。这不是 skill 的提升证据，也说明临时评分有盲点。保留旧题、答案和评分；主分析排除它。v1.0.1 改为独立 10,000 个测试样本，明确配对不一致计数及区间方法，另跑 [T10 补测](results/control-20261011-v101/summary.json)。不事后改旧分数来制造优势。

小样本、每条件一次、公开开发题和天花板效应，不支持跨模型、真实项目、长期工作流或额度节省结论。处理组只加载三份冻结文本；工具执行、plugin 和其他参考文件不在这轮因果比较范围内。时长受服务波动影响，不作为速度优势。下一步应新增更难且未公开的任务、冻结评分并安排独立人工校准，保留失败和并列结果。

[更新版完整回归](results/updated-20261011-v101/summary.json)另进行了 20 次生成、20 次盲评，结果仍为双方 40/40、8/8 陷阱、2/2 对照。这是同一开发题集的再次采样，不是新的独立任务证据；处理上下文是更新的入口与理论/实验两份参考，未加载压缩的审稿/投稿文件。后者经过独立只读审查和记录路径回归，不能声称其效果已被这轮模型对照验证。

## 可复制任务与评分

2026-10-25 新增[实证选题开发集](idea-selection-v1/README.md)，专门比较旧 skill 与新选题流程：五题临时评分为 18/20 与 20/20，完整答案与 I04 标签问题均保留在[结果说明](idea-selection-v1/RESULTS.md)。这个小型开发集不证明实际选题质量或评审认可提高，不改变下面的十题审计基线。

当前 [tasks.json](../skills/research-rigor/assets/rigor-eval/tasks.json) / [rubric.json](../skills/research-rigor/assets/rigor-eval/rubric.json) 是 v1.0.1。十题覆盖界的强度、泄漏、过度主张、变换秩、松弛优化证书、失败分母、预算公平、评审来源，以及两个有效对照。每题四项语义评分；关键错误单列，不能靠措辞或关键词得分。人工评分空表随 skill 打包。

详细生成、盲评和导出命令见 [评测协议](../skills/research-rigor/references/skill-evaluation.md)。运行会消耗用户已登录模型额度，计划冻结后不静默重试；失败也保留。模型名称需由运行者明确指定。

## 每项改动的功能回归

```text
python -m pip install -r skills/research-rigor/assets/theory-checks/requirements.txt
python evals/run.py --compare evals/functional-after-20261011.json --output evals/current.local.json
python -m unittest discover -s tests -v
```

[功能建设前基线](baseline-functional-20261011.json)记录 0/7 组：六组功能尚未建立、默认初始化不是三件套。新增用例后由 [run.py](run.py)运行引用、数字、轻量升级、封存 hook、理论搜索、plugin/参考文件和默认文件数。新增用例的 `same_test=false` 必须保留：这是能力建立前后对比，**不是相同模型题上的提升率**。对已有组发生失败必须修复；新增功能应增加能复现真实缺陷的合成用例。

[本次功能结果](functional-after-20261011.json)为 7/7 组通过。CI 在 Windows/Linux、Python 3.11/3.13 上运行回归。今后每项修改保留原基线，输出新报告并检查测试哈希；修改评测任务/评分需升级版本并解释，不能覆盖旧结果。引用测试用公开或合成元数据，不发送私有论文。hook 测试使用临时项目，不触碰真实封存材料。

[文档体积](reference-footprint-20261011.json)记录两份长文从 28,273 字符降到 13,551 字符，约减少 52%。这是文件字符数，**不是实测 token 或账单降低**；入口按需加载仍比一次读完更重要。

[公开工具试跑](public-tool-smoke-20261011.json)：Crossref 与 arXiv 两条元数据均匹配；Semantic Scholar 一条匹配、一条接口失败并保留 unresolved。合成 SymPy 示例记录了真实反例和数值失败。Claude 原生加载未执行，本机没有其 CLI；只确认静态打包和 hook 协议/阻断测试。不能把这些结果说成所有接口或宿主都已验证。

## 发布证据边界

公开的任务、答案和评分均是合成材料。来源项目路径、身份、原始评审、未发表结果、模型原始事件日志与会话标识不发布。每个结果目录包含文件 SHA-256 清单；离线重算可核验。Git 对冻结结果禁止换行转换，保留原始字节。功能测试/实现的文本哈希使用 UTF-8、LF，以便跨平台比较。该清单验证文件一致性，不证明模型评分正确。
